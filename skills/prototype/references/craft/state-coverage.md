# 五状态覆盖契约

> AI 设计最可靠的失败是只画了有数据态。

有数据态（Populated）只是五个状态之一。只演示"happy path"的原型无法验证产品逻辑完整性，
而真实世界的用户一定会遇到空屏、错误与极端数据。**每个页面、每个关键组件必须覆盖五状态。**

## 五个必备状态

| 状态 | 触发条件 | 必备内容 |
|------|---------|---------|
| **Loading 加载中** | 数据请求进行中 | 骨架屏（与真实布局同构）或 spinner；占位保住布局，不跳动 |
| **Empty 空态** | 数据为零（新用户 / 筛选无结果） | 插画或图标 + 一行解释 + 主行动按钮 |
| **Error 错误** | 请求失败 / 校验失败 / 无权限 | 发生了什么 + 为什么 + 怎么办 + 重试入口 |
| **Populated 有数据** | 正常数据 | 真实感业务数据、真实感数量（不是恰好 3 条） |
| **Edge 极端** | 极限数据 | 超长文本、超大数字、单条记录、满页（分页边界）、特殊字符 |

## 表单专属状态

表单在五状态之外额外覆盖三态：

- **untouched 未触碰**：初始态，无校验提示；主 CTA 禁用或可点按设计系统约定
- **dirty 已修改**：字段级校验反馈——错误色 + 文字说明，不能只靠颜色（无障碍要求）
- **submitted-pending 提交中**：按钮 loading 态防重复提交，表单整体只读

## 空状态构成

三要素缺一不可：

1. **插画/图标** — 内联 SVG，风格与页面一致（单色线稿优先，禁止 emoji）
2. **一行解释** — 说明为何为空："暂无符合条件的工单"，不是"暂无数据"
3. **主行动** — 引导下一步："创建第一张工单"，而非只有"刷新"

筛选后的空状态必须提供"清除筛选"入口。

## 错误必须回答的三个问题

- **发生了什么**："无法连接服务器"，不是"系统错误"
- **为什么**（已知时）："网络可能不稳定" / "该字段为必填项"
- **怎么办**："请重试" / "请检查标红字段"

禁止向用户暴露技术堆栈；须保留错误 ID 供支持引用。

## 重试纪律

- 第 1 次重试：立即（用户手动触发）
- 自动重试：2s → 4s → 8s 退避
- 连续 3 次失败：停止自动重试，展示"请联系支持" + 错误 ID
- 长任务（上传 / 报表生成）须展示进度，不能只有 spinner

## 加载阈值

| 时长 | 策略 |
|------|------|
| 0–300ms | 不展示任何加载态（防闪烁） |
| 300ms–1s | 骨架屏（与真实内容布局同构） |
| 1s+ | 骨架 + spinner，或转入明确加载态 |
| 60s+ | 停止等待，转错误态并提供重试 |

## ARIA 与状态切换

- 加载容器 `aria-busy="true"`，完成后置 `false`
- 动态注入的错误信息 `aria-live="polite"`（紧急错误用 `assertive`）
- 状态切换管理焦点：提交失败后焦点回到第一个错误字段；弹层打开后焦点移入弹层
- 禁止用 `alert()` 呈现错误
