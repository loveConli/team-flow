# S3.5 产品级架构设计 SOP（v0.35.0，v0.14 §59/§60）

> architecture 阶段（S3 之后、S4 之前）的执行 SOP。产出 `docs/architecture/iterations/vN/architecture.md`（预测态快照）。
> **owner**：architecture-design skill 的 **product 模式**子代理（唯一 owner，声明见 architecture-design/SKILL.md「独立调用」扩展）。
> **时序（P1）**：只写快照不写全局；change 关闭时 arch-merge 回写实际增量；迭代收尾快照标 `archived` 退役。

## 输入

- prd/vN/prd.md（frozen_downstream，功能清单 F001_P0 等）
- prd/vN/plan.md（高阶技术设计段：模块边界/技术选型/数据流/关键聚合划分）
- prototype/（S2 产物，页面结构）
- docs/architecture/baseline.md（S1 注入）
- docs/architecture/CONCEPTS.md（领域词汇）
- 现有全局基线（旧项目逆向重建场景）

## 8 步执行流程

> 复用 architecture-design 方法论（F1-F8 + ch01-ch06），从"每 change 增量"扩展到"全系统结构级设计"。

| 步 | 动作 | 方法论 | 产出 |
|----|------|--------|------|
| 0 | 输入梳理 | 读 PRD 功能清单 + plan 技术方向 + prototype + CONCEPTS + 现有基线 | 功能域→候选业务能力映射 |
| 1 | 限界上下文识别 | 功能域分组 + 词汇聚类 + 活动对象矩阵（ch04，重叠>70% 合并） | Context Map：BC 表 + 关系图（6 关系类型）+ 语言边界术语表 |
| 2 | 聚合识别 | 聚合四要素（ch04）+ 活动对象矩阵 | 聚合注册表（唯一事实源） |
| 3 | 指令与事件识别 | CQRS 指令分流（ch05：Command/Read/Query + 阻断测试）+ 事件三类 | 指令表 + 事件表 + 事件流图 + 读模型投影清单 |
| 4 | 聚合状态迁移 | 聚合根=状态机守卫（Vernon） | stateDiagram + 状态表（含触发源上下文、guard 不变量） |
| 5 | 数据模型/ER（概念级） | 从聚合映射持久化（IA）+ CQRS 写读分区 | 聚合边界 ER + 实体表 + 聚合→表映射表 |
| 6 | 应用时序（关键用例） | AA→TA 编排（4A） | 关键用例 Top-N 跨聚合时序图 + 用例索引 |
| 7 | 跨域一致性检查 | F2 双对齐（AA≥1 IA 实体）+ 语义统一 + F3 变更分叉级联 | 一致性检查表 |
| 8 | 反模式自检 + 评审 | DDD 反模式清单 + 产品级评审门 | 自检清单 + 评审 verdict |

**顺序纪律**：聚合在前、ER 在后（ER 是派生产物，禁止先画 ER 再定聚合）；BC 边界/聚合所有权/全局契约是**产品级唯一事实源**（聚合注册表），变更级只引用。

**按域详细页产出（v0.36.3，domains/ 生产者）**：Step 1 识别 BC 后、Step 2-6 每个触及域细化时，同步产出 `domains/<bc>.md`（职责/聚合明细/指令事件/状态迁移/ER 局部/时序/对外契约）与 `diagrams/`（erd/sequences）——它们是按域分段加载（`s3.5-loading-protocol.md` 第②段）与 reviewer product A1 的审查对象；单文件 ≤1500 token。

**模板**：按 `references/s3.5-architecture-template.md` 骨架产出（6 产物 + 厚锚点 + marker + provenance）。

## 产品级评审门（Step 8）

复用 architecture-reviewer agent（`agents/architecture-reviewer.md`），以 **product 视角**审查：

| 维度 | 校验 |
|------|------|
| A1 | 结构完备（6 产物章节存在 + marker/锚点可解析，机械预检） |
| A2 | SQL/结构有效（机械 grep，若含 sql/） |
| A3 | 跨域一致性（AA↔IA 双对齐，F2 门禁） |
| A4 | 与 PRD 功能清单覆盖映射（F001_P0 逐条 → BC/聚合/API） |
| A5 | 与全局基线一致性（旧项目逆向重建产物 vs 现状代码） |
| A6 | conventions 合规 |

规则：≤3 轮修复循环 + 收敛检测（连续两轮不一致项不缩小 → 转人工）；PASS 才进 S4。
**skip 时**：architecture-reviewer 不执行，但 skip 必须物化（iterations/vN/SKIPPED 标记 + 理由）。

### 复利捕获（Step 9，v0.36.3 复利链路修复）

评审 PASS 后，捕获本次架构设计产生的可复用决策经验（advisory 级，捕获失败不阻断）：

- **触发场景**：BC 边界取舍、聚合划分理由、事件/读模型投影设计模式、技术选型决策、逆向重建低置信度修正
- **命令**：`tf solutions capture --phase architecture --domain <触及BC> --type pitfall|pattern --severity medium --summary "<经验>"`（source: `iterations/vN/architecture.md`）
- **注入端**：后续架构设计（变更级/产品级）执行时 `tf solutions inject --phase architecture` 自动注入这些经验（architecture-design 加载协议，v0.36.3）
- **晋升说明**：产品级架构经验直接 capture 写 `docs/solutions/`（不走 change 级 promote——promote 只认 `learnings.md`，是变更级机制）

## 正向设计 vs 逆向重建

| 维度 | 正向设计（全新/已建档） | 逆向重建（旧项目首轮） |
|------|------------------------|----------------------|
| 输入 | PRD/plan/原型（预测） | 既有代码/DDL/文档（事实） |
| 推导方向 | 业务能力→BC→聚合→... | 代码结构→候选 BC→聚合根候选→... |
| 工具 | 方法论 + LLM | recon-probe.sh + codebase-recon-analyst + arch-reverse-analyst |
| provenance | forward-designed | reverse-engineered + 置信度（high/medium/low） |
| 深度 | L0 骨架 + 触及域深化 | 同（首轮强制 L0 骨架，见 v0.14 §63.3） |

逆向重建工具：`workflow-bootstrap` 的 recon-probe.sh（--ddl-out，路径 `${CLAUDE_PLUGIN_ROOT}/skills/workflow-bootstrap/scripts/recon-probe.sh`）+ codebase-recon-analyst + 新增 `arch-reverse-analyst`（v0.14 §63.2）。

## 阶段产物同步门禁点（v0.37.0 §68.2 G2）

ARCH 完成（评审 PASS 或 skip 已物化）后，**阻塞确认**（AskUserQuestion）是否同步阶段产物（团队协作：架构决策是实施依据）：
- **A 提交并推送**：`tf publish --arch --push`
- **B 仅提交不推送**：`tf publish --arch`
- **C 暂不同步**：继续 S4，后续可补

同步对象：`docs/architecture/iterations/vN/`（架构快照）+ 评审 verdict（含首轮 `tf arch init` 打戳产物 `.team-flow/arch-state.json`）。

## 完成条件

- `docs/architecture/iterations/vN/architecture.md` 已产出（6 产物，provenance 标注）
- 产品级评审门 verdict = PASS（或 skip 已物化）
- orchestrator.yaml 中 ARCH 阶段状态 = completed（workflow_phase: architecture）
- **未触发** arch-merge 全局覆盖写（预测态不进实际态，P1）
- **架构基线打戳（v0.36.3）**：首轮项目（`arch_baseline` 缺失）评审 PASS 后执行 `tf arch init --mode reconstruction --baseline-ref prd/vN/`（旧项目逆向重建）或 `--mode design`（全新项目正向设计）——arch-readiness/arch-snapshot 门禁的豁免键在此建立，项目进入「已建档」正轨

## 常见陷阱

- **过度详设**：契约级（每 API schema/每表全字段）留给 change 落地涌现，产品级只做结构级（P4）。
- **skip 不物化**：跳过必须写 iterations/vN/SKIPPED + 理由，否则 S4 arch-readiness 卡死 hotfix 通道（v0.32.2 C1 死锁链同类）。
- **事件只识别不投影**：引入事件必须补"读模型投影清单"（§3.4），否则读模型更新无定义。
- **ER 先行**：先画 ER 再定聚合 = 数据库驱动设计，违背 DDD（顺序纪律）。
