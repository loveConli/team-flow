## 三、D7.1_业务流程

### 3.1 业务流程图

#### 3.1.1 Skill 协作协议层整体流程

##### 3.1.1.1 业务流程图：

| TF-COLLAB-001_Skill协作协议层整体流程 |
|---|
| 需求探索 (need-explorer) → PRD 生成 (ce-brainstorm) → 实施计划 (ce-plan) → 架构设计 (architecture-design) → 原型验证 (prototype) → Spec 编写 (spec-writer) → 代码构建 (build-executor) → 代码审查 (code-reviewer) → 变更合并 (spec-merger) → 复利回写 (release-archivist) |

##### 3.1.1.2 流程概要说明：

team-flow 插件包含 17 个 skill，覆盖产品研发全流程。四套独立体系（team-flow 9 个 skill、compound-engineering 6 个 skill、architecture-design 1 个 skill、prototype 1 个 skill）已拼合到一个 plugin.json 中，但 skill 之间的协作依赖隐式约定，缺少统一协作协议层。本次迭代旨在建立 Schema 声明式协议 + Handoff 模板的混合协作机制。

##### 3.1.1.3 流程步骤说明：

**步骤 1：PRD 对齐（Phase 1）**
- 改造 ce-brainstorm 使其读取可配置 PRD 模板（`prd.template` 配置字段）
- 产出 PRD 文档写入 `prd/vN/prd.md`（vN 为产品迭代版本）
- ce-brainstorm 启动时扫描 `prd/` 目录检测已有迭代版本

**步骤 2：Schema 协议层（Phase 2）**
- 每个 skill 的 SKILL.md frontmatter 增加 `input_schema` 和 `output_schema` 字段
- `input_schema` 声明消费的工件列表：`artifact`（文件名）、`required`（必须性）、`schema_ref`（JSON Schema 引用）
- `output_schema` 声明产出工件，额外包含 `consumed_by` 字段声明下游消费者
- 在 `team-flow/schemas/` 目录下维护关键衔接点的 JSON Schema 定义

**步骤 3：Handoff + DP 优化（Phase 3）**
- 每个 skill 完成时生成标准 `handoff.yaml`（字段：`from_skill`、`to_skill`、`timestamp`、`artifacts`、`context_summary`、`dp_digest`）
- 四套子系统衔接点使用专用 handoff 变体（`bridge_type` 字段区分）
- 每个 DP 触发 skill 从上游 handoff 自动提取结构化摘要

#### 3.1.2 四套子系统衔接边界

##### 3.1.2.1 业务流程图：

| TF-COLLAB-001-S2_四套子系统衔接 |
|---|
| compound-engineering (ce-brainstorm/ce-plan/ce-compound/ce-ideate/ce-proof/ce-strategy) ↔ bridge: ce-plan → spec-writer ↔ team-flow (spec-writer/spec-merger/build-executor/code-reviewer/workflow-start/contract-builder/e2e/bug-investigator/release-archivist) ↔ bridge: architecture-design → build-executor ↔ architecture-design (architecture-design) ↔ bridge: prototype → execution-contract ↔ prototype (prototype) |

##### 3.1.2.2 流程概要说明：

四套子系统的核心衔接点：
1. **ce-plan → spec-writer**：ce-plan 的实施计划需要无缝交接给 spec-writer 启动 change
2. **architecture-design → build-executor**：架构设计产出需要指导 build-executor 的代码生成
3. **prototype → execution-contract**：原型验证结果需要体现在 execution-contract 中

##### 3.1.2.3 流程步骤说明：

| 衔接点 | 上游 Skill | 下游 Skill | 交接工件 | 当前问题 | 改善方案 |
|---|---|---|---|---|---|
| ce-plan → spec-writer | ce-plan | spec-writer | prd/vN/prd.md (enriched) | 缺少显式 handoff，用户手动转述 | handoff.yaml 含 PRD 引用 + context_summary |
| architecture-design → build-executor | architecture-design | build-executor | design.md | 设计约束缺少结构化传递 | input_schema 声明 design.md 约束 |
| prototype → execution-contract | prototype | contract-builder | prototype/ + execution-contract.md | 原型验证结果与执行契约脱节 | handoff.yaml 含 bridge_type: prototype |
