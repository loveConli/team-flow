# 回顾模式：从会话中自动识别问题信号

> 本文件定义 workflow-feedback 回顾模式的问题识别规则。
> 回顾模式在无 argument 或由 release-archivist 联动时触发。

## 触发条件

- 用户调用 `/workflow-feedback` 但未传入 argument
- release-archivist 收尾时建议触发
- 用户说"回顾一下这次工作流"、"有什么问题吗"

## 问题信号识别

扫描当前会话，识别以下信号：

### 信号 1：skill 被纠正

**特征**：skill 被调用后，用户手动纠正了方向。

**识别模式**：
- 用户说"不是这个"、"我要的是 XX 不是 YY"
- skill 产出被用户大幅修改
- 用户取消了 skill 的执行

**映射分类**：`skill-trigger` 或 `ux-interaction`

### 信号 2：用户不满表达

**特征**：用户表达了对工作流的不满。

**识别模式**：
- "不对"、"不是这样"、"重来"
- "怎么又问这个"、"之前不是说过了吗"
- "太麻烦了"、"能不能简单点"

**映射分类**：根据不满对象判定（skill/流程/交互）

### 信号 3：状态回退

**特征**：发生了 mandatory rewind 或阶段回退。

**识别模式**：
- 状态从 executing 回到 specifying/bridging
- orchestrator 阶段从 S3 回到 S2
- replan_log 有新增条目

**映射分类**：`sop-flow`（回退本身可能是正常的，但频繁回退说明流程有问题）

### 信号 4：重复确认

**特征**：同一事项被确认多次。

**识别模式**：
- 用户回答了相同/相似的问题 2 次以上
- 模型在不同阶段问了同一个决策

**映射分类**：`ux-interaction`

### 信号 5：工作流中断/跳过

**特征**：工作流的某个步骤被跳过或中断。

**识别模式**：
- 用户说"跳过这步"、"先不管这个"
- 某个阶段被标记为 skipped
- 用户直接做了下一步该做的事

**映射分类**：`sop-flow`（跳过可能说明该步骤不必要或位置不对）

## 回顾输出格式

回顾完成后，按以下格式汇总：

```
本次会话工作流回顾：
- 检测到 N 个问题信号
- 按分类汇总：
  - skill-trigger: X 个
  - sop-flow: Y 个
  - ...
- 建议记录的问题（按 severity 排序）：
  1. [P?] <问题标题> — <分类>
  2. ...
- 是否要为这些问题生成 feedback 记录？
```

## 注意事项

1. **回顾不等于记录**：回顾模式先汇总信号，询问用户后再逐条生成记录
2. **误报容忍**：宁可多识别再让用户筛选，不要漏掉真正的问题
3. **不记录业务问题**：只关注工作流本身的问题，业务代码 bug 不算
4. **上下文限制**：只能分析当前会话的内容，无法跨会话分析
