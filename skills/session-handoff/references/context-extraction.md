# 上下文萃取规则（6 类隐性知识）

> 本文件定义 session-handoff Step 2 的萃取规则。
> 核心原则：萃取"只存在于对话上下文中的隐性知识"，已在产物中的信息只引用路径。

## 萃取分类

### 1. 进度摘要

**萃取方法**：回顾对话中的工作动作序列，归纳为三类：
- **已完成**：已经产出文件或已经确认的事项
- **正在进行**：当前正在处理但未完成的事项（标注卡点）
- **下一步**：紧接着要做的 1-3 件事

**注意**：进度是会话级的，不是项目级的。只记录本次会话的进展。

### 2. 关键决策

**萃取方法**：识别对话中用户确认或模型提出并被接受的决策，且该决策**尚未写入任何产物文件**。

**判断标准**：
- 如果决策已写入 PRD/plan/spec/design → 不记录，引用产物路径
- 如果决策只在对话中确认 → 记录到 §4

**典型场景**：
- "用方案 A 不用方案 B"（但未写入 design.md）
- "这个功能先不做"（但未更新 PRD scope）
- "用 X 库代替 Y 库"（但未更新 plan.md）

### 3. 未解决问题

**萃取方法**：识别对话中提出但未最终回答的问题，以及模型做出的临时假设。

**格式**：每个问题标注"默认处理"（当前按什么假设在继续）和"需要确认？"。

### 4. 用户偏好

**萃取方法**：识别用户表达的偏好、约束、风格要求，且这些偏好**不在任何项目文档中**。

**典型场景**：
- "我不喜欢太多确认弹窗"
- "代码风格偏向函数式"
- "先做核心功能，花里胡哨的后面的再说"
- "不要引入新的依赖"

### 5. 失败尝试

**萃取方法**：识别对话中尝试过但放弃的方案，记录放弃原因。

**价值**：防止新会话重新走一遍同样的死路。

**格式**：`方案 X：放弃原因 → ...`

### 6. 敏感信息

**萃取方法**：扫描对话和生成的文档内容，识别以下模式：
- API Key / Token / Secret
- 密码 / 凭据
- 个人身份信息（PII）

**处理**：全部替换为 `${PLACEHOLDER}`，在 §10 声明已脱敏。

## 萃取优先级

当对话内容过多时，按以下优先级取舍：

1. **必须**：进度摘要 + 下一步（没有这个新会话无法继续）
2. **重要**：关键决策 + 未解决问题（没有这个新会话可能走弯路）
3. **建议**：失败尝试 + 用户偏好（没有这个新会话可能重蹈覆辙）
4. **可选**：敏感信息声明（无敏感信息时可简化）
